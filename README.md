# Clip Reader

A Markdown clipboard reader with text-to-speech, packaged as a native
Android app -- **authored entirely in Python, entirely through
ARKlight, with zero hand-written Kotlin or Java.**

Paste Markdown copied anywhere on your phone, see it rendered as
formatted text, and have it read aloud.

## How this stays 100% ARKlight

- `site.py` is the whole app: the UI is ARKlight's Python component
  API (`Container`, `Button`, `Heading`, ...), and the one place this
  reaches past static markup -- reading the clipboard, parsing
  Markdown, driving speech -- is ARKlight's own documented
  `script-extension` escape hatch (`arklight.backend.script_extension
  .ScriptExtension`, see `docs/Foundational/EXPERIMENTAL-APIS.md` in
  the ARKlight repo). That JS is appended to `arklight.js`, the one
  runtime file every ARKlight page already ships -- it is not a
  second app, not injected some other way.
- `arklight android scaffold` generates the entire Android Studio /
  Gradle project (Kotlin, Gradle, the manifest -- all of it) from the
  `arklight build` output. **Its generated `MainActivity.kt` is used
  exactly as scaffolded -- nothing in this project edits, patches, or
  adds to it.** There is no `@JavascriptInterface`, no
  `addJavascriptInterface`, no native bridge of any kind, because
  ARKlight's own Android backend doesn't add one and this project
  doesn't either.
- Clipboard access and text-to-speech both come from **standard web
  platform APIs** that Chromium WebView (what `arklight android
  scaffold`'s `MainActivity.kt` embeds) already implements on top of
  the OS's own clipboard and TTS engine:
  - `navigator.clipboard.readText()`
  - `window.speechSynthesis` / `SpeechSynthesisUtterance`

  Both work because `WebViewAssetLoader` serves this app's assets
  under a fixed `https://appassets.androidplatform.net` origin
  (instead of `file://`), which is a secure context -- the
  precondition both APIs need to be available at all. This is the
  same mechanism note ARKlight's own `MainActivity.kt` docstring
  already calls out for `State(persist=True)` -> `localStorage`.

## Project layout

```
clip-reader/
├── arklight.config.py   # android app identity (name, package id, orientation, ...)
├── site.py               # the entire app: UI + the ClipReaderRuntime script extension
├── ARK/                  # `arklight build` output (static HTML/CSS/JS)
└── android/               # `arklight android scaffold` output (Android Studio project)
```

## Building it yourself

Requires the ARKlight compiler installed and its license accepted
(`ARKLIGHT_ACCEPT_LICENSE=1`, after reading its `LICENSE`):

```bash
# 1. Compile the Python-authored site to static HTML/CSS/JS.
arklight build site.py -o ARK

# 2. Generate the Android Studio / Gradle project from that build.
arklight android scaffold ARK -o android

# 3. Build the APK (needs a JDK + Android SDK on this machine --
#    arklight itself doesn't shell out to Gradle yet, see the
#    generated android/README.md).
cd android
gradle assembleDebug
```

`android/.github/workflows/android-build.yml` (also generated by step
2) builds and smoke-tests a debug APK in CI with no local toolchain at
all, if you push this to a GitHub repo.

## What it does

- **Paste** reads the clipboard and renders it as Markdown --
  headings, bold/italic, inline code and fenced code blocks, links,
  images, ordered/unordered lists, blockquotes, tables, and
  horizontal rules -- via a small dependency-free renderer (no CDN;
  the packaged app is fully offline).
- **Listen / Pause / Resume / Stop** read the rendered text aloud
  using the device's own TTS voices through `speechSynthesis`,
  including real pause/resume (the Web Speech API supports both
  natively -- there's no "stop and hope it looks like a pause" here).
- A **speed slider** (0.5x-1.8x) adjusts the speech rate live.
- **Clear** resets back to the empty state.
- Word count / reading-time / listening-time estimate in the status
  bar.

## Design notes

The visual language (serif reading face for the rendered body, a
single accent color reserved for the primary action, a quiet neutral
chrome) takes cues from how real reading/notes apps present long-form
text -- Bear, Obsidian's reading view, GitHub's rendered Markdown --
rather than looking like a generic form. All of it is ARKlight's own
`Site()`/`site.style()` API: CSS var overrides for the base font and
max width, named classes with `:hover`/`:active` pseudo-rules for
buttons, no raw stylesheet, no CSS file of its own.

A few rules specifically target the WebView, not the desktop-browser
preview build:

- `env(safe-area-inset-top/bottom)` padding on the top bar and footer,
  since `arklight.config.py` sets `edge_to_edge = True` for this app
  (content draws behind the system status/nav bars).
- `overscroll-behavior-y: contain` on the app shell so a clipboard
  interaction can't rubber-band the whole page like a website would.
- `-webkit-tap-highlight-color: transparent` + a pressed-down
  `:active` scale transform on every button, so taps feel like a
  native control's press state instead of a browser's blue tap flash.
- `accent-color` on the speed slider re-tints the browser's own native
  range input to this app's accent, without reimplementing the
  control.

## Known platform limits (both are Chromium WebView behavior, not a
gap in this project)

- `navigator.clipboard.readText()` still requires a user gesture and
  can prompt for a one-time permission the first time an app reads
  the clipboard, depending on the OS version -- this project can't
  and shouldn't route around that.
- Voice selection follows whatever TTS engine/voices are installed on
  the device; the app doesn't (and, without a native bridge, can't)
  offer a voice picker beyond the rate slider.
